# Fazenda Climate Control

Система автоматичного клімат-контролю для теплиці на базі ESP32 з веб-інтерфейсом та OTA оновленнями.

## Можливості

- Моніторинг температури та вологості (DHT22)
- 4-канальне управління вентиляцією з кікстартом
- Автоматичні цикли (outCold / outNormal / outHot)
- Захист від переохолодження (ColdLock) вдень і вночі
- Обігрів-термостат 20.0 / 21.0°C вдень і вночі
- Аварійний режим при відмові DHT (після 3 помилок поспіль)
- Автоматичне перемикання День/Ніч (фоторезистор, дебаунс 3 зчитування)
- Нічна логіка з вологісним контролем
- TFT дисплей ST7735 1.8" з анімацією каналів
- Веб-інтерфейс: OTA прошивка, перегляд логів, статус JSON
- SPIFFS логування з NTP часом (ротація файлів), вмикання/вимикання через Blynk V16
- Інтеграція з Blynk IoT
- Діагностика перезавантажень у Flash (автоскидання після 2 хв стабільної роботи)

## Встановлення

1. Клонуй репозиторій:
```bash
git clone https://github.com/KoshykOleg/Fazenda.git
cd Fazenda
```

2. Створи `src/secrets.h` з шаблону:
```bash
cp src/secrets.example.h src/secrets.h
```

3. Заповни `src/secrets.h`:
```cpp
#define WIFI_SSID       "твій_wifi"
#define WIFI_PASS       "твій_пароль"
#define BLYNK_AUTH_TOKEN "твій_токен_blynk"
#define OTA_PASSWORD    "пароль_для_ота"
```

4. Завантаж прошивку:
```bash
pio run -t upload
```

## Логування

### Формат запису
```
2026-04-01 21:33:23 50,23.0,62.1,3,0,DAY,FAN_CHANGE:CH0->CH3
```

| Поле | Опис |
|------|------|
| `2026-04-01 21:33:23` | Дата/час (NTP) або `[uptime s]` до синхронізації |
| `50` | Uptime (секунди) |
| `23.0` | Температура (°C) |
| `62.1` | Вологість (%) |
| `3` | Активний канал вентилятора (0–4) |
| `0` | Обігрів (0/1) |
| `DAY` / `NIGHT` | Режим роботи |
| `FAN_CHANGE:CH0->CH3` | Подія |

### Типи подій
- `BOOT` — запуск системи
- `BOOT_CYCLE` — вибір початкового циклу
- `FAN_CHANGE` — зміна каналу вентилятора
- `OVERHEAT` — перший старт при перегрітому повітрі
- `COLDLOCK` — активація/деактивація захисту від холоду
- `CYCLE_CHANGE` — зміна автоциклу (outCold/outNormal/outHot)
- `MODE_CHANGE` — перехід DAY↔NIGHT
- `DHT_ERROR` — помилка датчика
- `SYSTEM` — системні події (включення логування, очищення)

### Вмикання/вимикання логування
Blynk V16 (Button) — керує записом у SPIFFS. Стан зберігається у Flash між перезавантаженнями.

### Очищення логів
Serial Monitor → надіслати символ `C`

### Ротація
Файл `/climate.log` обрізається до останніх ~50 КБ (з першого повного рядка) при перевищенні 100 КБ.

## Налаштування

### Пороги логіки (climate.cpp)
```cpp
COLDLOCK_TEMP_LOW    17.5°C  — ColdLock вмикається при T < 17.5
COLDLOCK_EXIT_TEMP   19.5°C  — ColdLock знімається при T ≥ 19.5
HEAT_ON_TEMP         20.0°C  — обігрів вмикається при T ≤ 20.0
HEAT_OFF_TEMP        21.0°C  — обігрів вимикається при T ≥ 21.0
DHT_ERROR_LIMIT      3       — помилок DHT поспіль до аварійного режиму
HUM_OFFSET_HIGH      5%      — верхня зона вологості (config.h)
```

### Логіка День/Ніч

**Денний режим:**
- Вентиляція працює постійно (мінімум CH1), вимикає її тільки ColdLock
- Старт з OFF: одразу CH1 через кікстарт, цикл outCold/outNormal/outHot обирається за поточною T
- 4 температурні зони з гістерезисом (V15) та динамічним offset циклу
- Цикл перемикається з урахуванням напрямку: outNormal→outCold при спуску на CH1, outNormal→outHot при підйомі на CH4, outCold→outNormal при підйомі на CH3, outHot→outNormal при спуску на CH2

**Нічний режим** — 3 зони вологості (set_hum = V6, humHys = V12):
- старт з OFF: H < set_hum → CH1, інакше CH2
- CH1 → CH2 при H ≥ set_hum + humHys
- CH2 → CH1 при H ≤ set_hum − humHys
- CH2 → CH3 при H ≥ set_hum + 5% + humHys
- CH3 → CH2 при H ≤ set_hum + 5% − humHys

**ColdLock (однаково вдень і вночі):**
- T < 17.5°C: вентиляція вимикається
- T ≥ 19.5°C: ColdLock знімається; вдень цикл обирається за поточною T
- Перехід день/ніч не скидає ColdLock і не вмикає вентиляцію, поки він активний

**Обігрів (однаково вдень і вночі):** вмикається при T ≤ 20.0°C, вимикається при T ≥ 21.0°C, незалежно від ColdLock. При V10 OFF вимкнений; при старті системи (boot або V10 ON) з T ≤ 20.0°C вмикається на першому циклі контролю.

**Помилка DHT:**
- На екрані `ERR` з'являється одразу; вентиляція й обігрів не змінюються до 3-ї помилки поспіль
- Після 3-ї помилки — аварійний режим за датчиком світла: день CH3, ніч CH1 (з OFF через кікстарт); обігрів вимикається
- Ручний Boost (V0) має пріоритет — CH4
- Перемикання день/ніч працює і під час помилки

### Пороги День/Ніч (climate.cpp)
```
lightVal > 2500, 3 рази поспіль — перехід у нічний режим
lightVal < 1500, 3 рази поспіль — перехід у денний режим
```

### Інтервали (main.cpp)
```
CLIMATE_CHECK_INTERVAL  10 000 мс  — читання DHT та оновлення логіки
PREF_WRITE_DELAY         5 000 мс  — затримка запису налаштувань у Flash
PERIODIC_INTERVAL      120 000 мс  — інтервал periodical-логу (logger.h)
sendPeriodicData        60 000 мс  — відправка T/H у Blynk (V1, V2)
checkBlynkStatus        30 000 мс  — перевірка/перепідключення Blynk
SCREEN_RECOVERY         600 000 мс — апаратне відновлення TFT (tft.initR(), 10 хв)
KICKSTART_DURATION      5 000 мс  — кікстарт на CH4 при старті вентиляції з OFF (climate.h)
```

### Пріоритет у loop()
```
1. Реле + анімація (апаратний пріоритет)
2. Кікстарт (завершення переключення)
3. Клімат-контроль (читання DHT)
4. Оновлення дисплея (одразу після свіжих даних)
5. Periodic screen recovery
6. Мережа (Blynk, таймери)
7. NTP retry
8. Логування
9. Serial команди
```

### Управління через Blynk
| Pin | Функція | Напрямок |
|-----|---------|----------|
| V0 | Manual Boost (примусово CH4) | вхід |
| V1 | Поточна температура (°C) | вихід |
| V2 | Поточна вологість (%) | вихід |
| V3 | Активний канал вентилятора (0–4) | вихід |
| V4 | Стан обігріву (0/1) | вихід |
| V5 | Цільова температура (set_temp_day) | вхід |
| V6 | Порогова вологість нічного режиму (set_hum_limit) | вхід |
| V7 | День активний (1=день, 0=ніч) | вихід |
| V8 | Ніч активна (1=ніч, 0=день) | вихід |
| V9 | ColdLock активний (0/1) | вихід |
| V10 | Система ON/OFF | вхід |
| V11 | Помилка DHT (1 = 3+ помилки поспіль) | вихід |
| V12 | Гістерезис вологості нічних зон, % (humHys) | вхід |
| V15 | Гістерезис температури ×10 (1..50 → 0.1..5.0°C) | вхід |
| V16 | Logging ON/OFF (SPIFFS) | вхід |

## Діагностика

### Boot Diagnostics (Serial)
При кожному завантаженні виводить:
- Лічильник перезавантажень (автоматично скидається після 2 хв стабільної роботи)
- Попередній uptime
- Останні T/H, канал, помилки DHT

### Debug-вивід
У `config.h` перемкни:
```cpp
#define DEBUG_CLIMATE 1   // 1 = увімкнено (зараз), 0 = вимкнено (production)
```

## Changelog

### v2.7.0 (не випущено)
- Вдень вентиляція не вимикається за температурою: CH1 — мінімум, OFF тільки через ColdLock
- ColdLock однаковий вдень і вночі, діапазон 17.5–19.5°C; гістерезис V15 на нього не впливає
- Обігрів-термостат 20.0 / 21.0°C вдень і вночі (замість set_temp − 4 лише вночі / в ColdLock)
- Старт з OFF і вихід з ColdLock: цикл обирається за поточною T, без перезапису при виході на CH1
- `checkCycleTransition` враховує напрямок зміни каналу
- Перехід день/ніч більше не скидає ColdLock і не запускає вентиляцію під час нього
- DHT: реакція вентиляції з 3-ї помилки поспіль; аварійний режим день CH3 / ніч CH1; Boost має пріоритет; день/ніч перемикається і під час помилки
- Дисплей: зміна каналу під час анімації більше не розсинхронізує екран; `SYSTEM OFF` не перемальовується смужками каналів
- Прибрано невикористані `HUM_OFFSET_LOW` / `H_LOW`, опис нічних зон вологості виправлено
- Ротація логу починається з першого повного рядка (раніше перший рядок був обрізаний)
- Прибрано ручний offset температури (Blynk V13/V14): цільову температуру задає лише V5
- Старі ключі offset (`offset`, `lastOff`) видаляються з Flash при старті
- Подія `MODE_CHANGE` у лозі пише `ColdLock: fan OFF`, якщо вентиляцію не запущено через ColdLock
- Прибрано невикористані константи та поля (`CYCLE_CHANGE_DELAY`, `lastCycleChangeTime`, `NIGHT_TEMP_CHECK_INTERVAL`, `C_GRAY`, `LOG_RETENTION_DAYS`, `lastEventLog`, `lastLoggedChannel`)
- `KICKSTART_DURATION` винесено в `climate.h` і використано в `main.cpp`
- Додано нативні тести `test_native/`
